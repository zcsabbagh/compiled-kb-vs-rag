# Compiled Knowledge Bases vs. RAG: Experiment Prompt

## Overview

Run a controlled experiment comparing retrieval from LLM-compiled wiki pages against retrieval from raw document chunks for question answering. Core question: does offline compilation improve retrieval-augmented QA, and is the gain from compression, cross-referencing, or both?

## Environment

- All LLM calls go through OpenRouter. Key is set as `OPENROUTER_API_KEY` in shell.
- Base URL: `https://openrouter.ai/api/v1`
- Use the `openai` Python SDK pointed at OpenRouter.
- Python 3.11+, use `uv` for dependency management.

## Models (via OpenRouter)

| Role | Model ID | Input $/1M | Output $/1M |
|---|---|---|---|
| Compiler + Judge | `anthropic/claude-sonnet-4` | $3.00 | $15.00 |
| Generator (small) | `meta-llama/llama-3.1-8b-instruct` | $0.02 | $0.05 |
| Generator (large) | `anthropic/claude-sonnet-4` | $3.00 | $15.00 |
| Embeddings | `openai/text-embedding-3-small` | $0.02 | N/A |

**No 70B mid-tier model.** The budget doesn't support it. Two generators (8B vs Sonnet) give the cleanest contrast: if compilation helps the small model more than the large one, that's the finding. The 70B is an optional follow-up if results are promising and budget remains.

## Budget Estimate

### Phase 1: Compilation (one-time cost, ~$9)

- **Corpus:** 100 papers, ~8k tokens avg extracted text = ~800k input tokens total
- **Condition B (summaries):** 100 calls, ~8k input + ~1k output each
  - Cost: (800k * $3 + 100k * $15) / 1M = $2.40 + $1.50 = **~$4**
- **Condition C (wiki):** Process in 10 batches of 10 papers. Each batch reads ~80k tokens of raw text + existing wiki (~20k growing), outputs ~10k of wiki updates.
  - Cost: (~1M input + ~100k output) * Sonnet rates = **~$4.50**
- **Lint pass:** One pass reading full wiki (~100k) + output (~10k) = **~$0.45**
- **Compilation total: ~$9**

### Phase 2: Question generation (one-time, ~$2)

- Generate 120 questions (sufficient for paired significance tests)
  - 50 factual, 50 synthesis, 20 contradiction
- ~200k input tokens (context from corpus), ~30k output
- Cost: **~$1.05**

### Phase 3: Embedding + indexing (~$0.02)

- 3 corpora * ~500 chunks * 512 tokens = ~768k tokens total
- At $0.02/1M: basically free

### Phase 4: Experiment runs (~$7.30)

**Per query:** ~5k input tokens (k=5 * ~1k/chunk + prompt), ~300 output tokens.

**Llama 8B:** 3 conditions * 120 questions = 360 calls = **~$0.05**

**Sonnet:** 3 conditions * 120 questions = 360 calls
- 1.87M input * $3/1M + 108k output * $15/1M = **~$7.25**

**Context-stuffing (D, E): DROPPED.** Loading ~100k tokens/call * 240 calls * Sonnet = ~$72. Blows the budget. These are a weaker contribution anyway; the retrieval comparison is the novel claim.

### Phase 5: LLM judge (~$5)

- 720 calls (correctness + faithfulness for each answer)
- ~600 input + ~100 output tokens per call
- **~$5 total**

### Summary

| Phase | Cost |
|---|---|
| Compilation (B + C) | ~$9 |
| Question generation | ~$2 |
| Embeddings | ~$0.02 |
| 8B generator runs | ~$0.05 |
| Sonnet generator runs | ~$7.25 |
| LLM judge | ~$5 |
| Buffer (retries, debugging) | ~$5 |
| **Total** | **~$28** |

Leaves ~$20 headroom for corpus-size ablation or a 70B pass if warranted.

## 3 Conditions

| | Retrieval | Corpus |
|---|---|---|
| A | RAG (k=5) | Raw document chunks |
| B | RAG (k=5) | LLM summaries (compressed, no links) |
| C | RAG (k=5) | LLM wiki (compressed + interlinked) |

B vs C isolates cross-referencing. A vs B isolates compression. A vs C is the headline number.

## Dataset

1. **Source corpus:** Download 100 recent arXiv papers on RLHF/RLAIF (2023-2026) via arXiv API. Store PDFs in `data/raw/`. Extract text with PyMuPDF into `data/raw_text/`.

2. **Question set:** 120 questions generated by Sonnet, three tiers:
   - **Tier 1 -- Factual extraction** (50): Single-paper answers.
   - **Tier 2 -- Cross-paper synthesis** (50): Require 2-4 papers.
   - **Tier 3 -- Contradiction detection** (20): Where papers disagree.

   Schema: `{"id", "question", "gold_answer", "source_paper_ids", "tier"}`
   Stored as `data/questions.jsonl`.

## Corpus Preparation

### Condition A: Raw chunks
- Chunk extracted text at 512 tokens, 64 token overlap.
- Store in `data/corpora/raw_chunks/`.

### Condition B: Summary-only
- Sonnet summarizes each paper individually. No cross-references.
- Prompt: "Summarize this paper's key contributions, methods, results, and limitations. Do not reference other papers. Output as markdown."
- Store in `data/corpora/summaries/`, then chunk at 512 tokens.

### Condition C: Compiled wiki
- Sonnet compiles the full corpus into interlinked wiki pages (Karpathy architecture).
- Process in batches of 10 papers. Each batch: read papers, update/create concept, entity, and method pages with `[[backlinks]]`.
- After all batches: lint pass for contradictions, missing links, index creation.
- Store in `data/corpora/wiki/`, then chunk at 512 tokens.

## Retrieval Setup

- Embedding: `openai/text-embedding-3-small` via OpenRouter.
- Vector store: ChromaDB (local, persistent).
- For each condition, embed and index corresponding chunks.
- At query time: embed question, retrieve top-k chunks (k=5), pass as context.

## Generator Models

1. **Small:** `meta-llama/llama-3.1-8b-instruct`
2. **Large:** `anthropic/claude-sonnet-4`

System prompt (same for both):
```
You are a research assistant. Answer the question using ONLY the provided context. If the context is insufficient, say so. Cite specific papers or wiki pages when possible. Be concise.
```

Temperature: 0 for all calls.

## Evaluation

For each (condition, model, question) triple:

1. **Correctness (all):** Sonnet judge, 1-5 scale.
   ```
   Given this gold answer and generated answer, rate correctness 1-5.
   1=completely wrong, 3=partially correct, 5=fully correct.
   Respond with JSON only: {"score": int, "reasoning": str}
   ```

2. **Faithfulness (all):** Sonnet judge.
   ```
   Given this retrieved context and generated answer, does the answer contain claims not supported by the context?
   Respond with JSON only: {"faithful": bool, "unsupported_claims": [str]}
   ```

3. **Coverage (tier 2 only):** Fraction of ground-truth source papers reflected in answer.

4. **Contradiction detection rate (tier 3 only):** Did model identify the disagreement?

5. **Token cost per query:** Log from API response `usage` field.

Results schema: `{"question_id", "condition", "model", "k", "answer", "correctness_score", "faithful", "coverage", "contradiction_detected", "input_tokens", "output_tokens"}`
Store as `results/raw_results.jsonl`.

## Analysis

Generate in `analysis/`:

1. **Main table:** Mean correctness +/- SE per (condition * model), broken out by question tier.
2. **B vs C test:** Paired Wilcoxon signed-rank test on correctness scores. This is the key result isolating cross-referencing value.
3. **Model interaction:** Is the A-to-C improvement larger for 8B than Sonnet? Report effect sizes (Cohen's d).
4. **Corpus size ablation:** Re-run A vs C at 50 papers with 8B only (cheap). Plot correctness vs corpus size.
5. **Cost-accuracy scatter:** Mean correctness vs mean token cost per (condition * model).

## OpenRouter Client Setup

```python
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://openrouter.ai/api/v1",
    api_key=os.environ["OPENROUTER_API_KEY"],
)

# Embeddings
resp = client.embeddings.create(
    model="openai/text-embedding-3-small",
    input="text to embed"
)

# Chat completions
resp = client.chat.completions.create(
    model="meta-llama/llama-3.1-8b-instruct",
    messages=[{"role": "system", "content": "..."}, {"role": "user", "content": "..."}],
    temperature=0,
)
```

## Caching

- Cache ALL API responses to disk keyed by `hash(model + messages)`.
- Use `diskcache` library. Store in `cache/`.
- On re-run, skip cached calls. Critical for debugging without burning budget.

## Cost Tracking

- After every API call, append to `results/cost_log.jsonl`:
  `{"timestamp", "model", "input_tokens", "output_tokens", "cost_usd", "cumulative_usd"}`
- Print running total after each script.
- **HARD STOP: if cumulative cost exceeds $45, halt all scripts and report.**

## Rate Limiting

- Llama 8B (may hit free tier): 20 req/min max. Add 3s sleep between calls.
- Sonnet: respect OpenRouter limits. Add 1s sleep between calls.
- Exponential backoff on 429 errors (base 5s, max 60s, 5 retries).
