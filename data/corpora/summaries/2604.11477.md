# OOM-RL: Out-of-Money Reinforcement Learning Market-Driven Alignment for LLM-Based Multi-Agent Systems

## Contributions

The paper introduces four key contributions to AI alignment for multi-agent systems:

1. **OOM-RL Framework**: Formalizes Out-of-Money Reinforcement Learning as an objective alignment paradigm that uses real-world financial friction as an "un-hackable negative gradient" to bridge the simulation-to-reality gap through iterative adaptation.

2. **STDAW Architecture**: Designs the Strict Test-Driven Agentic Workflow, an adversarial engineering framework utilizing uni-directional state locking (RO-Lock) to prevent "Test Evasion" - where agents modify test assertions to artificially inflate coverage without fulfilling business logic.

3. **Longitudinal Empirical Study**: Presents a 20-month live deployment study (July 2024 – February 2026) documenting the system's evolution from high-turnover, sycophantic trading behavior to a resilient, liquidity-aware architecture that internalizes financial penalties.

4. **RLFCB Conceptualization**: Proposes Reinforcement Learning from Cloud Billing as a domain-agnostic extension that frames computational resource depletion as generalized physical friction for non-financial multi-agent systems.

## Methods

The methodology centers on a dual-loop adversarial architecture that decouples logical verification from empirical survival:

**Inner Loop (STDAW)**: Enforces a deterministic constraint matrix with ≥95% code coverage across an 8,300-line codebase. The RO-Lock mechanism prevents agents from simultaneously acting as "Creator" and "Judge" by mounting test directories as read-only volumes during verification phases and implementing AST-based sanitization to prevent monkey-patching attempts.

**Outer Loop (OOM-RL)**: Deploys the system in live financial markets where the reward function ROOM-RL is defined as:
- Baseline return: R̃t = Σ(ωi,t × ri,t) - Fexec(Δωt)
- Terminal penalty: ROOM-RL = R̃t if Lt < τ, else -Pterminal
- Where Lt represents cumulative principal loss and τ = 0.20 (20% drawdown threshold)

**Epistemic Autopsy Prompting**: Translates scalar financial penalties into structured JSON prompts for human-supervised architectural refactoring, constraining agent actions to AST-based code mutagenesis rather than full file rewrites.

## Key Results

**Performance Evolution**: The system achieved dramatic improvement across three phases:
- Phase 1 (Daily turnover): 11.01% annualized return, Sharpe ratio 0.35, -16.86% max drawdown
- Phase 2 (Weekly rebalancing): 13.55% annualized return, Sharpe ratio 0.91, -6.85% max drawdown  
- Phase 3 (Mature STDAW): 34.48% annualized return, Sharpe ratio 2.06, -5.50% max drawdown

**Statistical Significance**: In the mature phase (94 trading days), OLS regression yielded:
- Market Beta: 0.83 (t = 10.60, p < 0.001)
- Daily Alpha: 12.03 basis points (annualized 30.07%)
- Alpha t-statistic: 1.71 (p = 0.0915, marginally significant at 10% level)

**Friction Impact**: Initial deployment revealed severe execution friction averaging ~0.08% per single-sided transaction. With 6700% annualized turnover, this compounded into significant capital drain that "completely eradicated the simulated alpha."

**Information Ratio**: Improved from -2.27 (Phase 1) to 2.66 (Phase 3), demonstrating successful transition from capital-destructive to alpha-generating behavior.

## Limitations

**Statistical Power**: The mature phase alpha coefficient (p = 0.0915) falls short of conventional 5% significance, achieving only marginal significance at the 10% level over the 94-day evaluation window.

**Human Dependency**: The system requires significant human intervention for architectural transitions. The authors explicitly state that "we do not claim that the LLM spontaneously deduced market microstructure" and that pivotal transitions were "operationally, a manual human intervention."

**Scalability Constraints**: The approach is limited by "prohibitive cost and ethical implications of parallel capital deployment in adversarial markets," preventing controlled experimental comparisons.

**Domain Specificity**: While the authors propose RLFCB as a generalization, the empirical validation is limited to financial markets, leaving questions about transferability to other domains.

**Evaluation Methodology**: The longitudinal self-evolution framework lacks parallel control groups, making it difficult to isolate the specific contributions of OOM-RL versus other factors in the system's improvement.

**Terminology Ambiguity**: Despite being framed as "Reinforcement Learning," the system does not perform gradient-based weight updates on LLMs, instead relying on human-in-the-loop in-context learning, which may mislead readers about the technical approach.
